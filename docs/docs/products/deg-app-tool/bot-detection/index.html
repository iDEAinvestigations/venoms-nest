DEG App Tool - Bot Detection & User-Agent Reference

Bot Detection Overview​

The User-Agent Analyzer can identify over 20 types of bots and automated tools. Understanding bot patterns is valuable for:

  • Security monitoring
  • Traffic analysis
  • Spam detection
  • OSINT investigations
  • Web scraping detection

Security Indicators​

The analyzer flags certain patterns as potential security concerns:

Headless Browser​

What It Is: Browser without graphical user interface, often used in automation

Pattern: Includes "HeadlessChrome" or "HeadlessFirefox"

Example:

Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like Gecko) HeadlessChrome/120.0.0.0 Safari/537.36

Implications:

  • Likely automated access
  • Could be legitimate testing
  • Could be malicious bot activity
  • Warrants investigation

WebView​

What It Is: Embedded browser component used in apps

Pattern: Includes "Version/" with no "Safari/" or browser name

Example:

Mozilla/5.0 (Linux; Android 13) AppleWebKit/537.36 (KHTML, like Gecko) Version/4.0 Chrome/120.0.0.0 Mobile Safari/537.36

Implications:

  • Accessed from within an app
  • Not a full browser
  • Limited functionality
  • May not execute JavaScript properly

Suspicious Patterns​

Characteristics That Trigger Warnings:

  • Missing expected components
  • Unusual combination of headers
  • Truncated or malformed strings
  • Spoofed or modified User-Agents
  • Known malware/botnet patterns

Using Bot Detection for OSINT​

Identify Legitimate Crawlers​

Google, Bing, Yahoo crawlers are expected traffic:

✓ Normal: Googlebot crawling site
✓ Normal: Bingbot indexing content
✓ Normal: Yahoo Slurp visiting pages

Identify Suspicious Bots​

Scrapers and automated tools accessing content:

⚠ Suspicious: Unknown automation tool
⚠ Suspicious: Headless browser scraping
⚠ Suspicious: Rapid requests from bot

Combined Analysis​

For complete investigation:

  1. User-Agent → Device and bot type (this tool)
  2. IP Address → Location and ISP (IP Lookup tool)
  3. Timestamp → When accessed
  4. Request Pattern → Frequency and volume
  5. Referrer → How they found you

Example Investigation​

Log Entry:
192.168.1.100 - - [15/Jan/2026:10:30:45] "GET /page HTTP/1.1" 200 1234 "-" "WhatsApp/2.23.20 iOS/16.5.1"

Analysis:
1. User-Agent: WhatsApp/2.23.20 iOS/16.5.1 (iPhone app)
2. IP: 192.168.1.100 (check with IP Lookup tool)
3. Time: 10:30:45 on January 15
4. Pattern: Single access (not scraping)
5. Conclusion: Legitimate person clicked link from WhatsApp
